The repository is a reference database, not an execution engine.

User Production Command → Worker → GitHub References → Prompt Design → Image Generation

GitHub stores reusable reference material. It does not control Worker lifecycle, discovery when the repository is explicitly supplied, prompt gates, queues, leases, retries, sessions, batch state, scheduling, or orchestration.

Manual and automated production share the same design process; automation only adds execution of the designed Prompt.

Removed historical specifications remain recoverable through Git history but are not production inputs.
