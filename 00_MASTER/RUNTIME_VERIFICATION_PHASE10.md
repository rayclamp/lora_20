# Runtime Verification — Phase 10 Image Provider Adapter Boundary

## Purpose

Phase 10 establishes the explicit boundary between the Worker Runtime and an actual image-generation provider.

The Worker owns:
- user-request interpretation;
- design;
- executable Prompt construction and locking;
- authorization;
- task ownership;
- result state.

The Image Provider Adapter owns:
- transport to the selected image-generation provider;
- provider request identity;
- provider execution telemetry when exposed;
- provider output metadata.

## Contract

The Worker must hand the provider adapter the exact locked Prompt.

The adapter must preserve:
- executable Prompt;
- Prompt hash;
- OUTPUT_TYPE;
- task identity;
- trace identity.

A provider result must resolve to:
- SUCCESS;
- FAILED;
- UNKNOWN.

Provider-specific telemetry must never be fabricated. Missing request IDs or executed-prompt telemetry are recorded as NOT_OBSERVABLE.

## Verification

`scripts/test_phase10_provider_adapter_boundary.mjs` verifies:
- exact Prompt handoff;
- Prompt hash propagation;
- provider request identity;
- output-format metadata propagation;
- invalid empty Prompt rejection.

The test uses a deterministic transport double and does not invoke a live image provider.

## Current boundary

Phase 10 proves the integration seam required for a real provider.

It does **not** prove that a real external image service is connected.

The next live-production gate requires a concrete provider selection and an authorized executable transport implementation. Until then, the system remains provider-ready but not live-provider-certified.

## Safety boundary

No ComfyUI orchestration is required by this architecture.

No Make scenario is activated by Phase 10.

No LoRA production is activated.

No production image is generated by this verification.
